## 系統架構與多工算力調度系統

本工具在面臨數萬個加密資產 Bundle 檔案的掃描、解密與寫入任務時，設計了高並行的多工架構，以平衡系統負載、降低 I/O 延遲，並在各種硬體規格上實作穩定的防護邊界。

### 1. QThreadPool 與 TaskWorker 的同步橋樑
為防止大量檔案讀寫或影像處理阻塞 Qt GUI 的主事件迴圈 (Event Loop)，本工具實作了繼承自 `QRunnable` 的 `TaskWorker` 執行緒元件。透過自訂的 `WorkerSignals`，背景執行緒能將進度計數、中間狀態以執行緒安全 (Thread-Safe) 的方式發送至主視窗，實作介面的即時渲染更新而不假死。

### 2. 多行程 (ProcessPoolExecutor) 算力釋放
對於 CPU 密集型的任務 (如解密二進位資料庫、大量圖集裁切、像素去背運算)，本工具採用 `concurrent.futures.ProcessPoolExecutor` 實作多行程並行計算。此設計有效繞過了 Python 的全域解釋器鎖 (GIL)，使多核心處理器能夠充分調度所有邏輯核心。各子行程在啟動時，會經由 `_init_worker` 複製主行程的語言字典，確保跨行程記憶體隔離時，錯誤訊息的語意對齊。

### 3. 作業系統級記憶體防護 (Memory Radar)
在批次處理大型動畫影格解碼時，C++ 底層函式庫可能會在記憶體中殘留大量未被垃圾回收 (GC) 的緩衝區。為防止實體記憶體耗盡導致作業系統強制終止行程，工具透過 `ctypes` 調用 Windows 核心的 `GlobalMemoryStatusEx` API，即時監控系統記憶體負載。當實體記憶體使用率達到 85% 的臨界值時，並行執行緒將暫時掛起並進入自適應休眠狀態，直至記憶體釋放，以確保系統穩定。

### 4. os.walk 動態剪枝演算法
在大規模掃描遊戲目錄時，為了避免無效路徑與自訂輸出目錄 (如暫存目錄、備份目錄) 導致 `os.walk` 陷入無限遞迴或產生冗餘的硬碟 I/O，本工具實作了 `prune_walk_dirs` 動態剪枝。在進入每一層目錄前，演算法會預先計算輸出路徑與當前路徑的物理子路徑關係 (`is_subpath`)，並直接修改 `dirs` 串列以截斷遞迴路徑。

## 二進位解密與資料庫反向工程

遊戲內的關鍵文字與卡片屬性 (如 card_name.bytes、card_prop.bytes) 均經過二進位混淆與壓縮。本專案透過分析其底層二進位分佈，實作了高效的解碼與對齊引擎。

### 5. 自訂 XOR 混淆解密公式
遊戲內部的二進位加密採用了基於位元位移與動態因子的 XOR 混淆。解密公式如下：
```python
decrypted[i] = raw_bytes[i] ^ (((i + key + 0x23D) * key ^ (i % 7)) & 0xFF)
```
其中 `i` 為位元組流的絕對索引，`key` 為混淆密鑰。

### 6. 啟發式密鑰自動猜解 (Bruteforce Crack)
當遊戲版本更新導致預設密鑰 (預設值 61) 失效時，本工具實作了 `auto_crack_key` 猜解引擎。演算法在 0 至 1023 的有限密鑰空間內進行迭代，將解密後的位元組流輸入 `zlib` 解壓縮模組。由於正常的解密檔案解壓後會包含明確的指標與 `YDLZ` 等特徵結構，而錯誤解密則會觸發解壓例外。本工具以此作為啟發式驗證指標，實作無需靜態定位偏移量的自我修復能力。

### 7. 全域 6-bit 卡片屬性解析模型 (Card Property Parsing)
為了解析卡片的真實種類 (Type) 與子種類 (SubType)，演算法直接介入 `card_prop.bytes` 二進位結構。此模型透過 O(1) 查表法，實現了極致的解析效能，其核心邏輯與位元組定義如下：

* **偏移量對齊與區塊讀取**：依據 `card_indx.bytes` 計算出的索引，以每 8 Bytes 為一個資料塊 (Chunk) 進行讀取。
* **資料萃取與位元遮罩**：
  * 資料塊的前 2 Bytes (`chunk[0:2]`) 為小端序無符號短整數 (`<H`)，代表卡片 ID (`cid`)。
  * 第 3 個位元組 (`chunk[2]`) 儲存了主要屬性。演算法對其執行位元及運算 (`& 0x3F`) 剝離高位元雜訊，取得純淨的 6-bit 代碼 (`b_clean`)。
  * 第 7 個位元組 (`chunk[6]`) 儲存了魔法與陷阱卡的次要屬性標記。
* **例外攔截器 (Paradox Defense)**：遊戲資料庫中存在已知悖論資料，例如 ID 4644 (紅葉的女王)。常規解析會導致分類崩潰，系統在進入查表前設立攔截器，若判定為此 ID 則強制指派 `Type="怪獸"`, `SubType="融合=非效果"` 並提早回傳。
* **智能保底防線 (Failsafe)**：為防範未來遊戲更新加入極罕見的未收錄代碼，當遭遇未知 `b_clean` 數值時，系統會自動將其安全降級分類為「效果怪獸」，並將未知的十六進位代碼記錄於 `Raw_Data`，確保後續 UI 渲染與相框套用流程絕對不會中斷。

### 8. Il2Cpp Metadata 輕量化二進位正則掃描
非卡片物件 (如場地、卡套、頭像) 的中文描述並未儲存在常規卡片資料庫中。本工具捨棄了繁重的完整 Il2Cpp 反編譯方案，實作了輕量化的二進位正則掃描。透過直接搜尋 `global-metadata.dat` 檔案中吻合 `ID([0-9]{6,7})` 格式的字串字元流，提取出所有潛在的明文 ID。

### 9. CRC32 雜湊校驗與對齊
對於掃描到的配件 ID，演算法會對其組合字串 (如 `f"IDS_ITEM.ID{id}"`) 進行二進位編碼，並計算其無符號 32 位元 CRC32 雜湊值 (`zlib.crc32(x) & 0xFFFFFFFF`)。隨後，將此雜湊值格式化為 8 位數十六進位字串，與經過 `msgpack` 解碼出的 `ids_item.bytes` 對照表進行交叉對齊，精準還原配件的中文明文。

## 多維度分詞與資料檢索引擎

### 10. 雙向同化與分詞搜尋 (Tokenizer & Fuzzy Search)
在「找出檔案」與「快捷單卡」的檢索框中，本工具實作了無依賴庫的純 Python 高階搜尋引擎：
* **NFKC 雙向同化**：利用 `unicodedata.normalize('NFKC', text)` 將全形字元、半形字元、平假名與片假名進行標準化。同時藉由正則替換統一遊戲內特有的引號。
* **語法樹分詞器**：支援布林運算邏輯。搜尋字串會被解析為包含詞 (`+`)、排除詞 (`-`) 以及精確片語 (`"..."`) 集合。
* **滑動視窗模糊比對**：在嚴格比對失敗時，啟用 `difflib.SequenceMatcher`，並採用滑動視窗 (Sliding Window) 演算法切片比對效果文，確保長文本中的局部特徵亦能被高容錯率地捕捉。
* **矩陣式屬性篩選**：結合上述解析出的 `Type` 與 `SubType`，允許透過勾選框進行多維度交集篩選。

## Spine 動畫重建與影像處理管線

對於超框卡圖與 Spine 召喚動畫 (Cut-In)，本工具實作了高度整合的影像重建演算法與 2D 動畫骨骼數學映射。

### 11. 預乘 Alpha (Premultiplied Alpha) 邊緣邊框淨化
Spine 骨骼動畫在 Unity 引擎中通常採用預乘 Alpha 混合。普通的 RGBA 圖片直接導入會導致半透明邊緣產生嚴重的黑邊與抗鋸齒失真。本工具的 `apply_premultiplied_alpha` 演算法利用 NumPy 的向量化運算，將 RGB 顏色值與 Alpha 通道進行歸一化相乘：
```python
Color_new = Color_orig * (Alpha / 255.0)
```
此矩陣運算徹底消除了邊緣的雜訊，重現了原廠級的透明漸層與光暈發光效果。

### 12. 綠幕去背與溢色修正演算法 (Chroma Key & Despill)
針對使用者匯入的 MP4 或實拍影片素材，系統內建了純粹矩陣運算的去背引擎：
* **色彩空間歐幾里得距離**：計算每個像素與目標去背色 (Target Color) 之間的三維距離 `sqrt((r-tr)^2 + (g-tg)^2 + (b-tb)^2)`。若距離大於容差值 (Tolerance)，則判定為保留區域，並支援高斯模糊 (GaussianBlur) 羽化邊緣。
* **防溢色修飾 (Despill)**：影片邊緣經常會反射綠幕的光線。演算法會判定當前像素是否由綠色主導 (`g > r` 且 `g > b`)，若是，則將綠色通道壓制為紅藍通道的最大值 `min(g, max(r, b))`，並依據溢色修正強度比例混入原始色彩，還原邊緣的自然採光。

### 13. 高度降冪貨架排版 (Shelf Packing) 與 POT 對齊
為了將動畫的多個影格整合成一張紋理圖集 (Texture Atlas)，演算法首先將所有子圖片依據裁切後的高度 (Bounding Box Height) 進行降冪排序，依次在設定的最大尺寸 (如 8192x8192) 畫布上從左至右進行橫向排版。在每張子圖片邊緣強制注入 2 像素的防溢色空隙。排版結束後，將最終畫布的尺寸向上湊齊至最接近的 2 的指數倍 (Power-of-Two, POT)，大幅優化顯示卡在執行時的記憶體對齊與紋理壓縮 (BC7) 效能。

### 14. Spine 4.2.43 召喚動畫坐標轉換與骨骼平移
遊戲官方的 Spine 動畫解析度基準為 4800x2700。本工具在動態生成 `js-hd.json` 骨骼描述檔時，會自動解析使用者的手動像素偏移參數，並將其精確對齊至 Spine 的世界坐標系：
```python
Translate_world_x = (Offset_pixel_x / Canvas_width) * 4800.0
Translate_world_y = -(Offset_pixel_y / Canvas_height) * 2700.0
```
註：由於 PIL 影像座標 (Y 軸向下) 與 Spine 世界座標 (Y 軸向上) 相反，平移 Y 軸時會強制反轉符號，確保使用者在 UI 預覽中所見即所得。

### 15. 雙圖層超框合成與 Alpha 幾何布林挖空 (Z-Order Synthesis)
超框卡圖處理不僅僅是縮放裁切。在 `MODE_OVERFRAME` 模式中，演算法執行了複雜的圖層合成與遮罩計算：
* **多層渲染機制**：由底部向頂部依次繪製：背景底板 (`-bg`) -> 卡底背景 -> 效果文字欄 -> 卡圖框 -> 效果框 -> 卡名欄 -> 外框 -> 角色圖層 (`-ch`)。
* **幾何純化與布林交集**：為了讓角色圖層能夠「穿越」實體卡框而不被相框遮擋，演算法利用 NumPy 提取純淨相框的 Alpha 遮罩。將「角色圖層 Alpha > 0」的區域與「三大框 (外框、卡圖框、效果框)」的遮罩進行位元及交集運算 (`m_ch_art & m_3frames_clean`)。
* **自動挖空 (Punch Hole)**：將算出的交集區域在最終合成影像的 Alpha 通道中強制作廢 (`data[m_final_zero, 3] = 0`)。這使得卡片在遊戲內的 3D 著色器渲染時，相框部位會變為透明，由後方的角色圖層補位，實現無縫的 3D 破框立體感。

### 16. 遊戲內閃卡光澤著色器模擬 (Foil Shader Simulation)
為使 UI 預覽與輸出至卡圖上的烘焙效果能完美還原遊戲內的鑽石/皇家鏡碎特效，本專案在 Python 中使用高等數學刻劃了一套完整的 Shader：
* **IQ 餘弦光譜生成 (Cosine Palette)**：利用公式 `a + b * cos(2pi * (c*t + d))`，依據像素的 X/Y 座標、旋轉角度與波段頻率計算出平滑漸變的彩虹/香檳金/白金鑽色階矩陣。
* **高光銳利化 (High-Pass Focus)**：採用人類視覺亮度公式 `0.299R + 0.587G + 0.114B` 計算明度，並將其進行指數放大 `power(lum, sharpness)`，計算出亮度比率矩陣。再將此比率乘回 RGB 通道，成功將柔和的光譜收束成銳利的雷射反光帶，且不造成色相偏移。
* **柔光混色引擎 (Pegtop Soft Light)**：採用標準的 Pegtop 柔光混合公式：`(1 - 2*Foil) * Base^2 + 2*Base*Foil`。有別於傳統的濾色或相加模式，此演算法能完美保留底層卡圖的凹凸紋理與深色輪廓，讓閃光效果猶如實體印刷般滲透進圖層之中。

### 17. PSD 多圖層備用隔離渲染演算法 (Fallback Layer Isolation)
為了自動讀取卡框模板，工具整合了 `psd-tools`。考慮到智慧型圖層或特殊通道混合模式可能導致直接複合渲染 (Composite) 崩潰，程式實作了雙軌隔離渲染：
* 軌道一：嘗試常規局部圖層渲染與偏移對齊。
* 軌道二 (Fallback)：若軌道一發生例外，系統會暫時將 PSD 的所有圖層可見度狀態備份並全部設定為隱藏，僅單獨點亮目標圖層及其父群組通道，調用全域影像渲染。此方法能繞過局部渲染的限制，相容所有的複雜圖層樣式，渲染完成後再復原所有圖層的可見度。

## 記憶體安全直接注入與註冊表重構

對於大型大廳背景及超框白名單註冊，本工具實作了無損的二進位資料修改，完全避開了解包與重新打包帶來的結構損壞風險。

### 18. Unity Bundle 貼圖色彩空間與資料流注入
* **串流解綁 (Stream Severing)**：在處理大廳背景 (如 `data.unity3d`) 或舊模組串流修復時，程式將 `m_StreamData` 結構中的 `path`, `offset`, `size` 全部強制清空為 0，切斷 Unity 引擎對外部巨型資源檔 (.resS) 的依賴與尋址。
* **直接覆寫**：將 PIL 或 OpenCV 處理完畢的影像資料轉換為 raw bytes，直接賦值給 Texture2D 的 `image_data` 屬性。
* **Gamma 空間校正**：當替換的檔案符合 `p\d+` (召喚動畫貼圖) 正規特徵時，程式會介入資料流，將 Unity 的 `m_ColorSpace` 屬性強制覆寫為 `0` (線性空間)。這排除了引擎將 sRGB 圖片進行二次 Gamma 校正的可能，徹底解決了模組動畫進入遊戲後色彩泛白、飽和度流失的長久痛點。

### 19. `of_card_asset` 註冊表二進位重構與增量合併
超框立體卡圖白名單儲存在 `of_card_asset` 檔案中。本工具將其作為 TextAsset 載入並實作了絕對安全的修改機制：
* **位元組解包 (Unpacking)**：利用 `struct.unpack("<HH", ...)` 將腳本位元組流以每 4 Bytes 為一組，解開為兩個小端序的 16 位元無符號短整數 (Trigger ID 與 Target ID)。
* **增量差異比對 (Incremental Diff)**：每次讀取註冊表時，系統都會在快取目錄尋找純淨的 `.pristine` 原裝備份。利用 Python 字典解析比對兩者的差異，精確提煉出「純粹由玩家自訂修改的差集」。
* **衝突攔截與寫入**：在寫入新註冊名單時，系統會比對玩家輸入的目標 ID，若遇到官方原有的特殊佔位符 (指向 0) 或同項目指向不同目標的邏輯矛盾，將觸發安全中斷。驗證通過後，將差集與最新版的官方基底合併，透過 `struct.pack("<HH")` 重新封裝為二進位流寫回資產。此技術確保了即便遊戲進行大改版，玩家辛苦建立的超框白名單依然能跨版本無縫轉移。

## 虛擬掛載事務與安全回滾機制

虛擬模組管理器採用 Windows 符號連結 (Symlink) 技術，旨在實作零硬碟空間佔用的即時模組套用與測試。

### 20. 符號連結交易防禦與回滾機制 (Rollback Engine)
在建立軟連結前，管理器會先對目標遊戲原檔進行備份，重新命名為 `.vanilla_backup`。在建立符號連結時，為了防範中途發生權限不足 (非管理員執行) 或檔案被遊戲程序鎖定佔用，工具實作了「原子性交易事務 (Atomic Transaction)」：
程式會在 `symlink_state.json` 中即時紀錄所有的備份與連結對照軌跡 (State Log)。如果在任何一個檔案的 Symlink 建立過程中拋出作業系統例外，回滾引擎將會立刻介入並終止後續迴圈。引擎會讀取 JSON 軌跡紀錄，將本次任務中所有已建立的幽靈連結強行解除 (`os.unlink`)，同時將對應的備份檔案復原歸位。此設計確保遊戲資料夾結構始終保持一致性，不留殘缺的半成品。

### 21. 智慧最長前綴匹配 (Longest Prefix Match)
在改圖替換與自動化封裝流程中，為了允許使用者自訂更具辨識度的圖檔名稱 (例如將 `12345.png` 命名為 `12345_冰劍龍_中文異圖.png`)，本工具捨棄了死板的 `split('_')[0]` 切割法，實作了最長前綴匹配。
演算法會將所有的自訂名稱讀取並依照字元長度降冪排序，由最長的字串開始嘗試與 CSV 字典中的有效卡片 ID 進行匹配 (`test_str.startswith(prefix)`)。比對成功後，演算法實施邊界防護 (Boundary Check)：檢查被匹配字串後續的第一個字元必須為合法分隔符 (底線、減號、點號、空白) 或直接為字串結尾。這確保了不會將名為 `123456.png` 的卡片錯誤歸類至 ID `12345` 之下，實作高容錯度且高安全的批次命名相容性。

## 靜態分析與多語系動態萃取

為了在不增加維護成本的前提下提供完整的國際化 (i18n) 支援，本專案實作了抽象語法樹分析。

### 22. AST 抽象語法樹靜態字串萃取
本工具利用 Python 的 `ast` 模組，對程式碼進行靜態解析 (Static Analysis)，無需實際執行程式碼即可建構抽象語法樹。
演算法走訪所有的 `ast.Call` (調用節點) 與 `ast.keyword` (關鍵字參數節點)，精準提取出所有被包裹在 `_("...")` 內、`placeholder="..."` 浮水印內，以及側邊欄 `DEFAULT_TABS` 字典定義中的明文字串。隨後，演算法會自動與 Languages 目錄下的 `zh-tw.json` 進行鍵值對比對，保留玩家已手動調整過的翻譯內容，並將程式碼中新增的語句進行增量補齊、重新字典排序寫回 JSON，實作零人工干預的高自動化多語系字典迭代。

## 開發者與編譯環境相容性支援

### 23. PyInstaller FMOD 動態虛擬化 (Mocking)
在將專案編譯並打包為獨立 Windows 執行檔 (EXE) 時，遊戲引擎原生的 FMOD 音效模組依賴 (如 `fmod_toolkit`、`pyfmodex`) 常常會因為編譯環境缺少底層 C++ 執行期動態連結庫 (DLL) 而導致編譯後的程式在啟動瞬間拋出 `ImportError` 崩潰。
為了解除此底層依賴限制，工具在程式的最頂層定義了 `MockModule` 類別 (繼承自 `types.ModuleType`)。在 Python 直譯器嘗試載入其他模組前，透過攔截 `__getattr__` 魔術方法使其回傳空匿名函數 (`lambda *args, **kwargs: None`)，並在 `sys.modules` 字典中對 FMOD 的所有介面進行了動態 Mock 覆寫。此虛擬化手法完美消除了封裝時的 DLL 物理相依性，確保工具庫的輕量化與可攜性。

### 24. 自訂線性拖曳捲動事件過濾器 (Linear Drag-Scroll Filter)
針對 Qt 內建的 `QListWidget` 與 `QScrollArea` 在拖曳時手感生硬、且在滑鼠移出視窗外時會產生劇烈且無法阻斷的物理慣性震盪問題，本專案實作了 `LinearDragScrollFilter`。
過濾器透過 `installEventFilter` 徹底接管了視窗的滑鼠點擊與移動事件，並引入了浮點數像素累積器 (Scroll Accumulator)。它會將游標與視窗邊界的距離代入靈敏度係數進行小數點計算，並將不到 1 像素的微小位移暫存於水桶中。當累積滿整數後，再呼叫 QScrollBar 進行精準步進，剩餘的小數點則繼續保留。當滑鼠放開的瞬間，系統立即強制中止 `QTimer` 並清空累積器。這解決了 Qt 底層事件堆疊的慣性累積問題，達到了即停即止、極致流暢的現代網頁級捲動體驗。
