# MD AstellarTool (MD 阿斯特婭工具箱)

[![License](https://img.shields.io/github/license/LLKSENsei/AstellarTool-Master-Duel-Modding-Tool?color=2CC985)](LICENSE)
[![Python Version](https://img.shields.io/badge/python-3.10%2B-blue)]()
[![Platform](https://img.shields.io/badge/platform-Windows-lightgrey)]()
[![Price](https://img.shields.io/badge/Price-100%25%20Free-brightgreen)]()

本專案是一款專為《遊戲王 Master Duel》開發的自動化資產解析、資料庫反向工程、二進位貼圖注入、超框卡圖 (Over-Frame Art) 渲染，以及虛擬模組管理工具。

本工具基於 Python 3、PySide6、UnityPy 以及 NumPy 等底層庫構建，旨在解決遊戲資產客製化過程中的繁瑣流水線步驟、底層檔案結構加密、Spine 動畫坐標重構以及作業系統級檔案實體管理問題。

## 系統架構與多工算力調度系統

本工具在面臨數萬個加密資產 Bundle 檔案的掃描、解密與寫入任務時，設計了高並行的多工架構，以平衡系統負載、降低 I/O 延遲，並在各種硬體規格上實作穩定的防護邊界。

### 1. QThreadPool 與 TaskWorker 的同步橋樑
為防止大量檔案讀寫或影像處理阻塞 Qt GUI 的主事件迴圈（Event Loop），本工具實作了繼承自 `QRunnable` 的 `TaskWorker` 執行緒元件。透過自訂的 `WorkerSignals`，背景執行緒能將進度計數、中間狀態以執行緒安全（Thread-Safe）的方式發送至主視窗，實作介面的即時渲染更新而不假死。

### 2. 多行程（ProcessPoolExecutor）算力釋放
對於 CPU 密集型的任務（如解密二進位資料庫、大量圖集裁切、像素去背運算），本工具採用 `concurrent.futures.ProcessPoolExecutor` 實作多行程並行計算。此設計有效繞過了 Python 的全域解釋器鎖（GIL），使多核心處理器（例如 AMD R9 9950X 等高執行緒處理器）能夠充分調度所有邏輯核心。各子行程在啟動時，會經由 `_init_worker` 複製主行程的語言字典，確保跨行程記憶體隔離時，錯誤訊息的語意對齊。

### 3. 作業系統級記憶體防護（Memory Radar）
在批次處理大型動畫影格解碼時，C++ 底層函式庫可能會在記憶體中殘留大量未被垃圾回收（GC）的緩衝區。為防止實體記憶體耗盡導致作業系統強制終止行程，工具透過 `ctypes` 調用 Windows 核心的 `GlobalMemoryStatusEx` API，即時監控系統記憶體負載。當實體記憶體使用率達到 85% 的臨界值時，並行執行緒將暫時掛起並進入自適應休眠狀態，直至記憶體釋放，以確保系統穩定。

### 4. os.walk 動態剪枝演算法
在大規模掃描遊戲目錄時，為了避免無效路徑與自訂輸出目錄（如暫存目錄、備份目錄）導致 `os.walk` 陷入無限遞迴或產生冗餘的硬碟 I/O，本工具實作了 `prune_walk_dirs` 動態剪枝。在進入每一層目錄前，演算法會預先計算輸出路徑與當前路徑的物理子路徑關係（`is_subpath`），並直接修改 `dirs` 串列以截斷遞迴路徑。

## 二進位解密與資料庫反向工程

遊戲內的關鍵文字與卡片屬性（如 card_name.bytes、card_prop.bytes）均經過二進位混淆與壓縮。本專案透過分析其底層二進位分佈，實作了高效的解碼與對齊引擎。

### 5. 自訂 XOR 混淆解密公式
遊戲內部的二進位加密採用了基於位元位移與動態因子的 XOR 混淆。解密公式如下：

```
decrypted[i] = raw_bytes[i] ^ (((i + key + 0x23D) * key ^ (i % 7)) & 0xFF)
```

其中 `i` 為位元組流的絕對索引，`key` 為混淆密鑰。

### 6. 啟發式密鑰自動猜解（Bruteforce Crack）
當遊戲版本更新導致預設密鑰（如預設值 61）失效時，本工具實作了 `auto_crack_key` 猜解引擎。演算法在 0 至 1023 的有限密鑰空間內進行迭代，將解密後的位元組流輸入 `zlib` 解壓縮模組。由於正常的解密檔案解壓後會包含明確的指標與 `YDLZ` 等特徵結構，而錯誤解密則會觸發解壓例外。本工具以此作為啟發式驗證指標，實作無需靜態定位偏移量的自我修復能力。

### 7. Il2Cpp Metadata 輕量化二進位正則掃描
非卡片物件（如場地、卡套、頭像）的中文描述並未儲存在常規卡片資料庫中。為了解開這些配件的雜湊命名，本工具捨棄了繁重的完整 Il2Cpp 反編譯方案，實作了輕量化的二進位正則掃描。透過直接搜尋 `global-metadata.dat` 檔案中吻合 `ID([0-9]{6,7})` 格式的字串字元流，提取出所有潛在的明文 ID。

### 8. CRC32 雜湊校驗與對齊
對於掃描到的配件 ID，演算法會對其組合字串（如 `f"IDS_ITEM.ID{id}"`）進行二進位編碼，並計算其無符號 32 位元 CRC32 雜湊值（`zlib.crc32(x) & 0xFFFFFFFF`）。隨後，將此雜湊值格式化為 8 位數十六進位字串（或轉換為小端序二進位），與經過 `msgpack`（配置 `strict_map_key=False` 以相容二進位非嚴格鍵值）解碼出的 `ids_item.bytes` 對照表進行交叉對齊，精準還原配件的中文明文。

## Spine 動畫重建與影像處理管線

對於超框卡圖與 Spine 召喚動畫（Cut-In），本工具實作了對應的影像重建演算法與 2D 動畫骨骼數學映射。

### 9. 預乘 Alpha（Premultiplied Alpha）邊緣邊框淨化
Spine 骨骼動畫在 Unity 引擎中通常採用預乘 Alpha 混合。普通的 RGBA 圖片直接導入會導致半透明邊緣產生嚴重的黑邊與抗鋸齒失真。本工具的 `apply_premultiplied_alpha` 演算法利用 NumPy 的向量化運算，將 RGB 顏色值與 Alpha 通道進行歸一化相乘：

```
Color_new = Color_orig * (Alpha / 255.0)
```

此矩陣運算消除了邊緣的雜訊，重現了原廠級的透明漸層。

### 10. 高度降冪貨架排版（Shelf Packing）
為了將動畫的多個影格整合成一張紋理圖集（Texture Atlas），本工具實作了高度降冪貨架排版演算法。首先將所有子圖片依高度進行降冪排序，依次在設定的最大尺寸（如 8192x8192）畫布上從左至右、從上至下進行橫向排版。若當前行剩餘寬度不足，則開闢新行。在每張子圖片邊緣注入 2 像素的防溢色空隙，防範動態縮放時產生紋理採樣溢色。

### 11. POT（Power-of-Two）對齊與視訊記憶體最佳化
為使輸出的紋理圖集在 Unity 載入時能夠套用最高效的硬體紋理壓縮格式（如 BC7），排版結束後，演算法會將最終畫布的尺寸向上湊齊至最接近的 2 的指數倍（例如 1024, 2048, 4096, 8192）。此對齊方式能夠優化顯示卡（如 TUF 5070ti）在執行時的記憶體對齊與採樣效能。

### 12. Spine 4.2.43 召喚動畫坐標轉換與骨骼平移
遊戲官方的 Spine 動畫解析度基準為 4800x2700。本工具在讀寫 `js-hd.json` 時，會自動解析使用者的手動像素偏移參數（`offset_x`, `offset_y`），並將其精確對齊至 Spine 的世界坐標系：

```
Translate_world_x = (Offset_pixel_x / Canvas_width) * 4800.0
Translate_world_y = -(Offset_pixel_y / Canvas_height) * 2700.0
```

同時，根據使用者設定的 POP UP 彈出時機，利用內建的動態插值器（Interpolation）在時間軸上計算各關鍵幀的縮放比率，確保動畫渲染時的視覺對齊。

### 13. PSD 多圖層備用隔離渲染演算法（Fallback Layer Isolation）
為了自動合成超框卡片（PeriFrame、NameBox、ArtFrame、EffFrame、EffBox、BackGround 五個獨立圖層），工具整合了 `psd-tools`。考慮到智慧型圖層或特殊通道可能導致直接 composite 崩潰，程式實作了雙軌隔離渲染：
* 軌道一：嘗試常規局部圖層渲染與偏移對齊。
* 軌道二（Fallback）：若軌道一發生例外，系統會暫時將 PSD 的所有圖層可見度備份並全部關閉，僅單獨點亮目標圖層及其父群組，調用全域複合渲染（Composite），此方法能相容所有的複雜混合模式，渲染完成後再復原所有圖層的可見度。

## 記憶體安全直接注入與註冊表重構

對於大型大廳背景及超框白名單註冊，本工具實作了無損的二進位資料修改。

### 14. Unity Bundle 貼圖二進位直接注入
在處理大廳背景（如 `data.unity3d`）或舊模組串流修復時，常規的完整解包再打包方案不僅極度消耗系統效能，還可能導致資料結構不相容。本工具實作了記憶體直接注入技術：
在 UnityPy 載入對應物件後，程式會將 `m_StreamData` 結構中的 `path`, `offset`, `size` 全部強制清空，切斷其與外部大檔（.resS）的連結，隨後將解碼後的 raw bytes 直接寫入 Texture2D 的 `image_data` 屬性。此方法避免了解包崩潰，實作了安全注入。

### 15. `of_card_asset` 註冊表二進位重構
超框立體卡圖白名單儲存在 `of_card_asset` 檔案中。本工具將其作為 TextAsset 載入，利用 `<HH` 結構（小端序雙無符號短整數，代表 Trigger ID 與 Target ID）對其位元組流進行對齊解包。
在使用者輸入新的註冊卡片 ID 後，系統會對資料進行衝突檢查，排除官方既有的特殊佔位符與同項目指向不同目標的邏輯衝突，隨後將全新的對照鍵值對進行增量融合，重新打包為二進位資料寫回資產。

## 虛擬掛載事務與安全回滾機制

虛擬模組管理器採用 Windows 符號連結（Symlink）技術，旨在實作零硬碟空間佔用的即時模組套用與測試。

### 16. 符號連結交易防禦與回滾機制（Rollback Engine）
在建立軟連結前，管理器會先對目標遊戲原檔進行備份，重新命名為 `.vanilla_backup`。在建立符號連結時，為了防範中途發生權限不足（非管理員執行）或檔案被遊戲程序佔用，工具實作了「原子性交易事務」：
程式會在 `symlink_state.json` 中即時紀錄所有的備份與連結對照軌跡。一旦在任何一個檔案的 Symlink 建立過程中發生錯誤，回滾引擎將會立刻終止後續任務，並根據軌跡紀錄，將所有已建立的連結刪除，同時將備份檔案重新命名復原，確保遊戲檔案絕對完整，避免客戶端發生損壞。

### 17. 智慧最長前綴匹配（Longest Prefix Match）
在改圖替換與自動化流程中，為了允許使用者自訂更具辨識度的圖檔名稱（例如將 `12345.png` 命名為 `12345_冰劍龍_中文異圖.png`），本工具實作了最長前綴匹配。
演算法會將所有的自訂名稱讀取並降冪排序，由最長的字串開始嘗試與 CSV 字典中的有效卡片 ID 進行匹配。比對成功後，演算法會檢查匹配邊界（後續字元必須為底線、減號、點號或結尾），以確保不會將 `123456` 的卡片錯誤歸類至 `12345`，實作高容錯度且高安全的批次命名相容性。

## 靜態分析與多語系動態萃取

為了在不增加維護成本的前提下提供完整的國際化（i18n）支援，本專案實作了抽象語法樹分析。

### 18. AST 抽象語法樹靜態字串萃取
本工具利用 Python 的 `ast` 模組，對程式碼進行靜態解析（Static Analysis），無需實際執行程式碼即可建構抽象語法樹。
演算法走訪所有的 `ast.Call`（調用節點）與 `ast.keyword`（關鍵字參數節點），提取出所有被包裹在 `_("...")` 內、`placeholder="..."` 內，以及側邊欄 `DEFAULT_TABS` 定義中的明文字串。隨後，自動與 Languages 目錄下的 `zh-tw.json` 進行比對，保留已翻譯的內容，並自動將新字串增量補齊並重新排序，實作高自動化的多語系字典維護。

## 開發者與編譯環境相容性支援

### 19. PyInstaller FMOD 動態虛擬化
在將專案編譯並打包為獨立 Windows 執行檔（EXE）時，遊戲引擎原生的 FMOD 音效依賴（如 `fmod_toolkit`、`pyfmodex`）常常會因為缺少底層 C++ 執行期動態連結庫（DLL）而導致編譯後的程式在啟動時直接崩潰。
為了解除此依賴限制，工具在程式的最頂層定義了 `MockModule`（繼承自 `types.ModuleType`），在 Python 載入其他模組前，透過攔截 `__getattr__` 回傳空函數，在 `sys.modules` 中對 FMOD 的所有介面進行了動態 Mock 覆寫。此虛擬化手法消除了封裝時的 DLL 相依性，大幅提升了建置的可攜性。

### 20. 自訂線性拖曳捲動事件過濾器（Linear Drag-Scroll Filter）
針對 Qt 內建的 QListWidget 在拖曳時手感生硬、且在滑鼠移出視窗時會產生劇烈且無法關閉的物理慣性震盪問題，本專案實作了 `LinearDragScrollFilter`。
過濾器徹底接管了視窗的拖曳事件，並引入了浮點數像素累積器（Scroll Accumulator）。它會暫存不到 1 像素的微小位移，累積滿整數後再呼叫 QScrollBar 進行精準步進。這解決了慣性累積問題，達到了即停即止、極致流暢的現代網頁級滾動體驗。
